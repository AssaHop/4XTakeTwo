## Контекст

Продолжение сессии 5. Реализация системы `damageVs` / `targetClass` —
разный урон по классам целей — плюс авиационная механика (lifecycle + спаун

## Дизайн-решения (зафиксированы в ai-design-notes-tribes.md)

### Треугольник урона / классы целей

Три оружия образуют полную матрицу:

| Оружие | surface | air | sub |
|--------|---------|-----|-----|
| Main   | ×1.0    | —   | —   |
| Torp   | ×1.0    | —   | ×1.0 |
| Small  | ×1.0    | ×0.5 | —  |

Отсутствие ключа = оружие **физически не может выбрать** эту цель
(не 0 урона, а невозможность атаки на уровне target-selection).

Три класса целей: `'surface'` (все обычные корабли), `'air'` (AAF/ADB/ATB),
`'sub'` (WSB). Класс задаётся на цели, не на атакующем.

AAF — чистый истребитель (Small, ×0.5 по air) — ПВО.
WDD/WCC получили Small + частичное ПВО как контрмера к бомберам.
WDD дополнительно получил Torp — может топить WSB.

### damageVs как множитель, не абсолют

`weaponTypes.js` хранит множители (`surface: 1.0, air: 0.5`), не числа.
Реальный урон = `Math.round(unit.atDamage * damageVs[targetClass])`.
Так разница `atDamage` между юнитами (WDD=2, WCC=3) сохраняется;
правила про оружие живут только в `weaponTypes.js`.

### Авиация: две разные характеристики

Отсутствие ответки у ADB/ATB — **не** дальность (как в Polytopia по
дистанции), а явный флаг `noCounter: true` (Dagger-style).
Это два независимых механизма. Дистанционная защита от ответки — бесплатно
через существующую логику range. Флаг — явное исключение.
`noCounter` зарезервирован; counter-attack в `combatLogic.js` ещё не
реализован — механического эффекта пока нет.

### Принцип простоты урона для игрока

1. `Math.round` один раз в самом конце — дальше число целое.
2. Множители грубые: 1 / 0.5 / отсутствие. Не дроби.
3. Не накладывать несколько множителей одновременно; если появится новый —
   решать порядок явно в одном месте.

## Что сделано

### 1. weaponTypes.js — поле damageVs

```js
Main:  { damageVs: { surface: 1.0 } }
Torp:  { damageVs: { surface: 1.0, sub: 1.0 } }
Small: { damageVs: { surface: 1.0, air: 0.5 } }
```

### 2. classTemplates.js — полный пересмотр

Добавлено `targetClass` и `dangerScore` для всех юнитов:

| Тип | targetClass | dangerScore | Новое |
|-----|-------------|-------------|-------|
| WDD | surface | 15 | + Torp в weType |
| WCC | surface | 20 | — |
| WBB | surface | 10 | — |
| WSB | sub | 35 | — |
| WCA | surface | 45 | — |
| WLC | surface | 10 | — |
| WSS | surface | 30 | — |
| AAF | air | 20 | + atDamage=3, lifeTurns=6, noCounter=true |
| ADB | air | 35 | + atDamage=5, lifeTurns=4, noCounter=true |
| ATB | air | 35 | + atDamage=4, lifeTurns=4, noCounter=true |

WCA (45) > WSB/WSS/авиация (35/30/35) > WCC/WDD (20/15) > WBB/WLC (10).

До этого: `dangerBonus` в `scoreTarget` был захардкожен как
`{ WCC: 25, WDD: 15, WBB: 10 }` — авиация и WSB/WCA не учитывались.

### 3. units.js — поля конструктора и фильтр в getAttackableHexes

Конструктор теперь читает из `options`:
```js
this.dangerScore = options.dangerScore ?? 0;
this.lifeTurns   = options.lifeTurns   ?? null;
this.noCounter   = options.noCounter   ?? false;
this.targetClass = options.targetClass ?? 'surface';
```

`getAttackableHexes()`: перед проверкой LoS пропускаем цели
не поддерживаемых классов:
```js
if (config.damageVs && !(target.targetClass || 'surface') in config.damageVs)) continue;
```

### 4. combatLogic.js — getAttackDamage() + performAttack

Новая экспортируемая функция:
```js
export function getAttackDamage(attacker, target) {
  // перебирает weType, берёт max по damageVs[targetClass]
  // возвращает null если ни одно оружие не может поразить этот класс
}
```

`performAttack`: использует `getAttackDamage` вместо `atDamage`;
если вернулось `null` — предупреждение + `canAct = false` + ранний выход.

Логирование: `⚔️ WCC → WDD[surface] 3dmg → 7/10`.

### 5. attackState.js — рефактор scoreTarget + Шаг B

Импорт `getAttackDamage`.

В `execute()` — фильтрация liveTargets по атакуемости:
```js
const liveTargets = allTargets.filter(t => getAttackDamage(unit, t) !== null);
```

В `scoreTarget`:
- Заменён хардкод `dangerBonus[type]` → `target.dangerScore || 0`
- Проверка kill: `if (target.hp <= getAttackDamage(unit, target) ?? 0) score += 40`
- **Шаг B** (аналог `SimpleAgent.evalAttack`): если цель может нас убить
  ответным ударом и мы в зоне её атаки — штраф −60:
  ```js
  const counterDmg = getAttackDamage(target, unit) ?? 0;
  if (dist <= (target.atRange || 1) && counterDmg >= unit.hp) score -= 60;
  ```

### 6. aviationLogic.js — новый файл

`processAviationTurn(state, owner)`:
- `tickAviationLifetime`: декрементирует `lifeTurns` у авиаюнитов, удаляет
  выработавших ресурс
- `spawnFromWCA`: если жив WCA и текущей авиации < MAX_AVIATION(4) —
  спаунит следующий тип из цикла ATB→ADB→AAF→... на соседний свободный гекс

`resetAviationState()` — сбрасывает `spawnCycle` Map (вызывается при reset).

Подключено в:
- `events.js`: `processAviationTurn(state, currentAI)` перед `runAIForTurn`;
  `processAviationTurn(state, 'player1')` при `handleEndTurn`
- `aiManager.js`: `resetAviationState()` в `resetAIState()`

### 7. dominator.js — флит 5v5

До: 2 юнита player1 (WDD+WCC) vs 1 случайный тип врага.
После: симметричный флит per owner:
```js
const FLEET = ['WDD', 'WDD', 'WCC', 'WCC', 'WBB'];
spawnFleet('player1');
for (let i = 0; i < enemyCount; i++) spawnFleet(`enemy${i}`);
```
