# Калибровка баланса флота (WDD/WCC/WBB)

Реализация протокола B→1→2 для known-issue #35 (`docs/known-issues.md`) —
три последовательных headless-эксперимента через настоящий игровой AI
(`ai/aiManager.js:runAIForTurn`), не имитацию боевой формулы вручную.
Методология зафиксирована пользователем в чате сессии калибровки; здесь —
как её запускать и что каждый скрипт делает.

## Порядок запуска (обязателен: B → 1 → 2)

```bash
node scripts/balance/exp-b-sensitivity.mjs
# → таблица чувствительности HP/ATK/DEF на класс — РУЧНОЕ решение
#   пользователя по новым статам, затем правка src/core/classTemplates.js

node scripts/balance/exp1-composition-equal-count.mjs
# → если классы НЕ сопоставимы по ценности при равном числе юнитов —
#   стоп, возврат к эксперименту B, не переходить к эксперименту 2

node scripts/balance/exp2-composition-equal-budget.mjs
# → предложение новых SPAWN_COSTS (src/core/economyLogic.js)
```

Каждый скрипт можно перезапускать отдельно (например, чтобы добрать
выборку) — предыдущий CSV/summary с тем же именем (дата+эксперимент)
перезаписывается, старые датированные файлы в `results/` остаются как
архив прошлых раундов калибровки.

## Переменные окружения (тюнинг объёма выборки без правки кода)

| Скрипт | Переменная | По умолчанию | Смысл |
|---|---|---|---|
| exp-b | `EXPB_CONFIGS` | 100 | число случайных наборов статов |
| exp-b | `EXPB_SEEDS` | 5 | сидов карты на конфиг (×2 зеркалирование = партий на конфиг) |
| exp1 | `EXP1_TOTAL` | 6 | суммарное число юнитов на сторону |
| exp1 | `EXP1_GAMES` | 5 | сидов на пару составов (×2 зеркалирование) |
| exp1 | `EXP1_FULL_MATRIX` | 1 | 0 = случайная выборка пар вместо полной матрицы |
| exp1 | `EXP1_MAX_PAIRS` | 0 (без лимита) | верхний потолок числа пар |
| exp2 | `EXP2_GAMES` | 5 | сидов на пару составов (×2 зеркалирование) |
| exp2 | `EXP2_FULL_MATRIX` | 1 | 0 = случайная выборка пар вместо полной матрицы |
| exp2 | `EXP2_MAX_PAIRS` | 0 (без лимита) | верхний потолок числа пар |

Бюджет для эксперимента 2 подбирается автоматически (`lib/compositions.mjs:
findBudget`) так, чтобы получалось 8-12 составов, полностью расходующих
бюджет — под ТЕКУЩИЕ `SPAWN_COSTS` на момент запуска.

## Общий модуль — `lib/`

- **`harness.mjs`** — сам движок симуляции: одна партия от спауна до
  победы/лимита ходов через реальный `state.js`/`aiManager.js`/
  `combatLogic.js`/`captureLogic.js`/`scenarios/skirmish.js`. Обе стороны
  всегда `enemy0`/`enemy1` (`runAIForTurn` жёстко игнорирует `player1`).
  Экономика точек захвата отключена самым чистым способом — `tickResourcesForOwner`
  просто никогда не вызывается (подробности и обоснование — в комментариях
  файла). `mirroredPair()` — обязательное зеркалирование сторон (один сид
  карты, два прогона с обменом сторон), требуется протоколом для B, 1 и 2.
- **`domStub.mjs`** — минимальный Proxy-стаб `document`/`window`. Нужен не
  из-за верхнеуровневых DOM-обращений (их нет), а потому что
  `Unit.moveTo()` реально дёргает рендер-цепочку (`gameStateMachine.js` →
  `highlightManager.js` → `render.js`) на каждое движение юнита.
- **`csv.mjs`** — синхронный append-only CSV writer (через файловый
  дескриптор, не `WriteStream` — см. комментарий в файле про баг с фоновым
  запуском).
- **`regression.mjs`** — ручная реализация МНК (нормальные уравнения +
  Гаусс-Жордан) для эксперимента B и логистической регрессии (батч
  градиентный спуск) для экспериментов 1/2. Без ML-библиотек.
- **`compositions.mjs`** — перебор составов флота: по фиксированному числу
  юнитов (эксп. 1) и по фиксированному бюджету токенов (эксп. 2).

## Зафиксированные параметры этого раунда (не варьируются)

Дистанции (`atRange`/`moRange`, сейчас `range:3` у большинства оружия),
боевая формула (`combatLogic.js`), terrain-эффекты (`defenseBonus`,
всегда `1`), классы вне WDD/WCC/WBB. **Если любой из этих параметров
меняется — весь протокол B→1→2 нужно прогнать заново**, результаты этого
раунда становятся недействительными (обоснование — в `known-issues.md`
#35 и `docs/architecture.md`).

## Результаты

`results/YYYY-MM-DD-{exp-b,exp1,exp2}.csv` — сырые данные по партиям.
`results/YYYY-MM-DD-{exp-b,exp1,exp2}-summary.md` — таблицы коэффициентов/
предложений, сгенерированные скриптом.
